# SIH26228 Requirement Traceability

This matrix maps the SIH26228 capability requirements represented in the supplied project context to the repository after the desktop and report changes. A separate SIH problem-statement source document was not present in the repository. Requirement labels below therefore use the phrasing in the project context and its explicit SIH mapping; they are not presented as verbatim quotations from an unavailable original PDF.

**Status rule:** IMPLEMENTED means code exists and a reproducible demo or meaningful test exercises the capability. PARTIALLY IMPLEMENTED means only a narrower input, adapter, heuristic, or evidence path works. UNAVAILABLE means no working repository implementation was found. FUTURE means an identified capability is explicitly planned but not currently implemented; no listed row is classified FUTURE without repository evidence of a plan.

Demo references below use `python demos/run_full_assurance_demo.py`. The existing `tests/` directory is a mixture of standalone test scripts and pytest-discoverable checks. A full `pytest -q` currently reports 114 passed plus 16 setup errors because parameterized helper functions are collected without fixtures; this does not invalidate a successful demo, but it limits the test claim. See [REPRODUCIBILITY.md](REPRODUCIBILITY.md).

## Status totals

Counts are per matrix row (37 requirements total).

- **IMPLEMENTED: 21**
- **PARTIALLY IMPLEMENTED: 14**
- **UNAVAILABLE: 2**
- **FUTURE: 0**

The largest gaps are complete COCO/YOLO ingestion, ONNX inference, safe general PyTorch checkpoint execution, an actual injected dataset-attack workflow, calibrated risk outputs, trusted timestamp/freshness verification and a formal disposition workflow. A hash-only model identity result does not claim model safety; a statistical trigger candidate does not prove a backdoor; distribution shift does not by itself establish malicious manipulation.
